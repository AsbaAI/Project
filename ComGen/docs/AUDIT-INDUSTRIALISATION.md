# Audit d'industrialisation — ComGen

Phase A (audit) et Phase B (plan) de la mission d'industrialisation. Aucun
code n'a été modifié pour établir ce document. Chaque constat renvoie à un
fichier du dépôt ; un constat sans preuve est marqué « non vérifié ».

## 0. Verdict d'étape

**NOT READY pour la production.** La démonstration de bout en bout
fonctionne (324 tests Playwright verts), mais **aucune génération n'est
faite par un modèle réel**. Le verdict « PILOT READY » ou « PRODUCTION
READY » demanderait les éléments P0 ci-dessous, dont plusieurs supposent
des choix que seul le client peut faire (§5).

## 2. Problèmes critiques (P0)

1. **Aucune génération IA réelle.** Le produit ne fait aujourd'hui que
   simuler. C'est le point bloquant : rien d'autre ne peut être validé
   sur du contenu de production tant que ce point n'est pas traité.
2. **Pas de retries ni de reprise.** La génération est liée à la requête HTTP.
3. **Pas de file de travail.** `workers` est un squelette ; Redis n'est pas utilisé.
4. **Pas de santé ni de disponibilité.** Aucune route `health` / `ready`.
5. **Pas de sauvegarde ni de restauration testées.**
6. **Pas de journal d'audit général** non modifiable.
7. **Stockage des fichiers** : éphémère en démonstration ; S3 non imposé hors démonstration.
8. **Antivirus** : la démonstration tourne sans (`ANTIVIRUS_MODE=aucun`).
9. **Authentification d'entreprise** non configurée (dépend du client).
10. **Qualité générative jamais mesurée.**

### P1 — fiabilité, traçabilité, persistance, qualité

- Console d'observabilité : identifiant de trace, journal structuré masqué, filtres (agent, communication, période, statut, gravité). Accès aux traces détaillées restreint.
- Agent Control Center complet : activation, modèle, paramètres, outils, test isolé, restauration de version, entrées/sorties.
- Rôles alignés sur le besoin du client ; droit dédié à la modification d'agents.
- En-têtes de sécurité ; limitation de débit ; vérification de `COMGEN_ENV` au démarrage.
- Politique de rétention et purge planifiée.
- Tests de reprise, de persistance après redémarrage et de sécurité (injection).
- ITSM : `desactive` par défaut.

### P2 — performance, ergonomie, observabilité avancée

- Workflow Monitor.
- Tests de charge (§9), mesures de rendu front.
- Coûts mesurés à l'appel réel.

## 4. Ce qui n'est pas ici

- Aucune modification de code n'a été faite à ce stade.
- Le client de ce projet est présenté comme **TotalEnergies** dans la mission ;
  le dépôt, sa spécification et ses données de démonstration utilisent
  **Helvea** et **Kestrel**. Je n'ai rien renommé.

## 5. Décisions nécessaires avant P0

Ces choix ne m'appartiennent pas. Sans eux, le P0-7 ne peut pas démarrer
honnêtement :

1. **Fournisseur de modèle** et clé d'accès en environnement TEST (Anthropic
   ou autre, passerelle interne ?).
2. **Fournisseur d'identité** (Entra ID, autre OIDC) et ses paramètres.
3. **Stockage objet** (fournisseur, bucket, politique de rétention).
4. **Hébergement des workers** : un service qui reste allumé (ni Vercel ni
   une fonction serverless ne conviennent).
5. **Antivirus** : quel service, ou refus explicite avec consignation.
6. **Nom du client** : TotalEnergies ou les données de démonstration actuelles.

## 6. Procédure de déploiement et de rollback

**Non établie.** Le document `docs/DEPLOIEMENT.md` ne couvre que la démonstration
publique (Vercel + Neon). Une procédure de production demande les choix du §5.

## 7. Qualité générative — méthode proposée

- Golden dataset versionné, mêmes entrées pour chaque version.
- Métriques **déterministes** en priorité : nombres, dates, identifiants et
  noms propres identiques à la source (comparaison de chaînes) ; mentions
  obligatoires présentes ; couverture des faits ; longueur dans la cible.
- Un juge LLM ne sert qu'à signaler, jamais à valider seul.
- Résultats horodatés et reproductibles, comparés d'une version à l'autre.

## 8. Limites du présent audit

- Les constats « absent » reposent sur une recherche par motif dans le
  dépôt : un élément nommé autrement pourrait avoir été manqué. Les lignes
  citées ont été lues.
- Aucun test n'a été relancé pour cet audit ; les chiffres de tests viennent
  du dernier `pnpm check` et `pnpm test:e2e` verts (commit `e85fa2b`).

## 9. Tests de charge — prévus, non exécutés

Scénarios à mesurer une fois P0-5 en place : 1, 10 et 50 générations
simultanées ; 20 utilisateurs qui consultent le tableau de bord ; limite de
débit du fournisseur simulée. Mesures : latence p50/p95, taux d'erreur,
jetons, coût. **Aucune capacité ne sera annoncée sans ces résultats.**
